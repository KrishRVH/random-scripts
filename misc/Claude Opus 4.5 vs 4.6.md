# Claude Opus 4.5 vs 4.6: capability milestone or later operating baseline?

_Primary-source comparison checked October 1, 2026. This note does not change the milestone specification._

**Judgment:** Opus 4.5 is a defensible historical inflection point for practical agentic engineering. Compared with Opus 4, it combined a substantial coding improvement with a two-thirds reduction in token prices. Opus 4.6 raises the bar further, particularly for longer tasks and larger contexts. On October 1, 2026, the owner clarified that the **1M context cutoff is important to the first bar**. This is a hard requirement for cloud Milestone A1; local A2 retains more than 200K usable context on one RTX 4090. That requirement makes Opus 4.6 the appropriate reference for this specification, while preserving 4.5's significance as a coding and affordability inflection. Neither choice establishes a universal date when engineering agents became reliable.

Table sources: Anthropic's [Opus 4 announcement](https://www.anthropic.com/news/claude-4), [Opus 4.1 announcement](https://www.anthropic.com/news/claude-opus-4-1), [Opus 4.5 system card, §§2.3–2.5](https://www-cdn.anthropic.com/bf10f64990cfda0ba858290be7b8cc6317685f47.pdf), [Opus 4.6 system card, §§2.3–2.5](https://www-cdn.anthropic.com/14e4fb01875d2a69f646fa5e574dea2b1c0ff7b5.pdf), and the [4.5](https://www.anthropic.com/news/claude-opus-4-5) and [4.6](https://www.anthropic.com/news/claude-opus-4-6) release announcements.

The 4.5 announcement describes better judgment with ambiguous requests, fewer dead ends, and improved token efficiency. Anthropic reports matching Sonnet 4.5's best SWE-bench result at medium effort with 76% fewer output tokens, and surpassing it at high effort with 48% fewer. These efficiency comparisons are against **Sonnet 4.5**, not Opus 4.0. Customer reports of improved autonomy are useful corroboration, but are selected release testimonials. [Anthropic, Opus 4.5](https://www.anthropic.com/news/claude-opus-4-5)

4.6's strengths extend beyond issue repair: deeper debugging, more sustained execution, and larger codebase understanding. Its headline long-context retrieval example compares it with **Sonnet 4.5**, not Opus 4.5. Anthropic also acknowledges that deeper thinking can add latency and cost. Adaptive thinking, context compaction, and agent teams are relevant, but platform and harness features should not be credited entirely to the underlying model. [Anthropic, Opus 4.6](https://www.anthropic.com/news/claude-opus-4-6)

Independent long-task evidence prevents dismissing 4.6 as a small refinement. METR's corrected TH1.1 point estimates give these human-equivalent task horizons:

| Model    | 50% success horizon | 80% success horizon |
| -------- | ------------------: | ------------------: |
| Opus 4   |          1.67 hours |        20.4 minutes |
| Opus 4.1 |          1.67 hours |        23.5 minutes |
| Opus 4.5 |          4.88 hours |        49.4 minutes |
| Opus 4.6 |         11.98 hours |        69.9 minutes |

These measure **task difficulty expressed in human completion time**, not how long an agent runs unattended. The 50% horizon roughly triples from 4.0 to 4.5 and grows another 2.45× to 4.6. However, 4.5's 95% interval is approximately 2.70–10.40 hours; 4.6's is 5.28–60.56 hours. The intervals overlap substantially, and the 80% horizons are much shorter. They support progress in long-task capability, without proving dependable multi-hour handoffs. [METR dashboard and methodology](https://metr.org/time-horizons/), [corrected TH1.1 results](https://metr.org/assets/benchmark_results_1_1.yaml)

Comparability matters. Opus 4's original Terminal-bench 43.2% is from an earlier benchmark version and must not be subtracted from Terminal-Bench 2.0 results. The 4.5 and 4.6 system cards disclose different infrastructure configurations and thinking settings; the later 59.8% row is preferable for the 4.5 → 4.6 comparison. SWE-bench uses the same 500-problem Verified set, but 4.5's best result used no extended thinking and five trials, whereas 4.6 used adaptive thinking at maximum effort and 25 trials. The 81.4% result adds an explicit prompt encouraging extensive tool use and testing. These are evaluated systems, not isolated measurements of model weights. [4.5 system card](https://www-cdn.anthropic.com/bf10f64990cfda0ba858290be7b8cc6317685f47.pdf), [4.6 system card](https://www-cdn.anthropic.com/14e4fb01875d2a69f646fa5e574dea2b1c0ff7b5.pdf)

For this specification, **4.6 is the coherent anchor because the owner requires the 1M working-context envelope**. The milestone should emphasize that context requirement alongside coding judgment, vision, tool reliability, and sustained execution. The original claim that 4.6 was when substantial multi-hour work first became reliable is stronger than the evidence establishes: even the Opus 4 release reported a seven-hour autonomous refactor. A demonstration, benchmark horizon, and dependable operating threshold are different things. [Anthropic, Opus 4](https://www.anthropic.com/news/claude-4)
