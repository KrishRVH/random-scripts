0. Enterprise stack scope

This specification covers the current enterprise stack for LLM-driven maintenance and development: application code, interfaces, platform, network, data, security, observability, compliance, disaster recovery, FinOps, procurement, and agent-operability controls.

Application development

The paved road commits to Python, Django modular monoliths, FastAPI typed edges, React + Vite, TypeScript strict, OpenAPI, pytest/Vitest/Playwright, Ruff/mypy/Pyright, uv/pnpm, and monorepo-first topology.

Enterprise platform

The platform catalog covers pub/sub, cache, Gateway API + Envoy, Kubernetes, virtualization, GitOps, policy, supply chain, data governance, AI governance, DR, FinOps, and procurement.

Agent operability

The visuals and controls are selected for actionability: corpus × stability quadrant, code-selection spine, coverage map, and the safety-class × change-tier matrix.

1. Selection rubric for agent-operated technology

The governance controls matter, but the core selection question is how reliably the model can write, modify, and debug each technology from text.

Axis Meaning Why it matters for agents Low-score failure mode
CD · Corpus density Amount of public code, docs, incidents, tutorials, Q&A, and examples. LLMs recall APIs and idioms from frequency of exposure. A merely elegant tool with little corpus is expensive for agents. Hallucinated APIs, wrong flags, invalid config keys.
IS · Interface stability How consistently APIs, conventions, CLIs, file layouts, and runtime semantics behave. Stable interfaces keep examples, docs, generated code, and tool output useful across the estate. Ambiguous APIs, invalid config, or code that passes review but fails tool checks.
SD · Self-description Types, schemas, manifests, generated clients, declarative config, ownership metadata. Contracts in files beat contracts in human memory. Agents need systems to state their own rules. Invisible ownership boundaries and silent contract violations.
FD · Feedback determinism Compiler, type checker, linter, test, dry-run, policy, and plan quality. Agents converge by iterating against crisp failures. Fast deterministic feedback is the real developer experience. Slow, vague, flaky, or delayed errors.

3. Reference architecture: selection plane + governance plane + runtime plane

The reference topology has three planes: a selection plane for what agents build with, a governance/control plane for how changes are contained, and a runtime/operations plane where reconciled state lives.

4. Safety model: tool capability × change class

S0–S5 classify tool capability; T0–T3 classify change intent. They are orthogonal. A read-only log query can move from S1 to S3 when it touches production or regulated data; a deploy operation can move from T1 to T2 when it changes schema, cost, auth, or customer-visible behavior.

Class Capability Controls
S0 Read-only public knowledge No sensitive data; cacheable; no approval.
S1 Read-only internal context Identity, ACL trimming, audit, data-class checks.
S2 Non-production write Sandbox, branch/workspace scope, expiring credentials.
S3 Production read JIT access, redaction, query limits, ticket binding.
S4 Production change through control plane Human approval or policy waiver, rollback, SLO guard.
S5 Break-glass or irreversible Two-person approval, session recording, post-review.

T0 Docs, formatting, tests, safe patch bumps Auto-merge after green checks and size cap.

5. Repo and tool contracts

This section turns the selection and safety model into lintable files. A repo without these files is not agent-ready.

+
AGENTS.md
Build/test commands, current version targets, module map, safety warnings, allowed automation boundaries.
+
catalog-info.yaml
Owner, lifecycle, service dependencies, data class, SLO, dashboard, runbook, cost center.
+
openapi.yaml / asyncapi.yaml
Machine-readable API and event contracts with examples and compatibility policy.
+
pyproject.toml / package.json / tsconfig
Toolchain and strictness declared in repo, not implied by memory.
+
tests/ and evals/
Unit, integration, contract, golden-task, and agent-regression coverage.
+
runbooks/ and ADRs/
Executable remediation steps, rollback paths, rejected options, and migration context.
+
CODEOWNERS + SECURITY.md
Review routing, disclosure process, support policy, sensitive-data constraints.
+
SBOM/provenance artifacts
Generated in CI, signed, attached to release, stored as evidence.

Automation surface

Does the product expose complete APIs, webhooks, event streams, CLIs, Terraform/OpenTofu provider, Kubernetes operator, or MCP/OpenAPI-compatible tooling?

Identity

Does it support OIDC/SAML, SCIM, workload identity/federation, short-lived credentials, fine-grained RBAC/ABAC, and audit trails?

Observability

Can it emit or integrate with OpenTelemetry, structured logs, metrics, traces, audit export, and cost attribution?

Data control

Can data be exported, deleted, region-pinned, encrypted with customer keys, and excluded from model training or cross-tenant processing?

Governance

Can policy be defined as code, reviewed in Git, tested in CI, and mapped to evidence for compliance?

Agent safety

Can tool operations be scoped, dry-run, approved, replayed, rate-limited, cancelled, and bound to a user/ticket/task?

Exit

Is there a documented migration path, open format, self-hosted option, or portable standard behind critical state?

12. Agent-hostile anti-patterns

These are not stylistic preferences. Each anti-pattern removes a safety boundary, context source, or reversibility path that LLM-driven maintenance depends on.

  • Click-only admin consoles for production changes.
  • Broad agent service accounts or shared API keys.
  • Prompts used as access-control boundaries.
  • Unstructured logs, unversioned events, and missing correlation IDs.
  • Agent code execution on privileged CI runners.
  • Mutable infrastructure changed outside Git/IaC.
  • No SBOM, provenance, or artifact signing for agent-built outputs.
  • Vector stores with outdated, unpermissioned, or unverifiable chunks.
  • Manual DR and backup evidence.
  • Permanent feature flags, temporary exceptions, or unowned queues.
  • Model/provider keys embedded in services instead of routed through a gateway.
  • Generated code accepted without contracts, tests, and blast-radius analysis.
