§1.0

Architectural Position

Managed-first · compiler-first · evidence-driven

This standard defines the paved road for greenfield or substantially rebuilt business software in which agents perform most implementation and routine maintenance while humans retain product judgment and high-impact approval. The governing objective is reliable delegated change with the smallest practical operational surface.

The architecture makes one deliberate strategic bet: Azure-centered managed infrastructure around a .NET 10 application core, with portability concentrated at seams that are realistically exportable—OCI, PostgreSQL, OpenAPI, OpenTelemetry, OAuth/OIDC, and Git. Cloud neutrality is not treated as a higher good than deleting operational work.

C# 14 · .NET 10 LTS

application core

ASP.NET Core provides compiled contracts, nullability, analyzers, first-party hosting integration, and a broad managed ecosystem suitable for repeated unattended modification.

Azure Container Apps

runtime

Managed ingress, scaling, revisions, jobs, identity, and service discovery remove the need for an application team to operate a cluster control plane.

GitHub pull requests + CI

change authority

Git is the change and evidence plane. Runtime values may live in managed systems, but schemas, ownership, policy, approvals, and privileged changes remain reviewable and attributable.

Razor Pages by default

product UI

Ordinary forms, workflows, portals, and administrative surfaces stay inside one application architecture. React is reserved for products that genuinely require rich client-owned state.

Modular monolith first

topology

Service extraction requires measured scale, compliance, latency, or ownership evidence and a migration ADR. Local context is treated as an agent-performance resource.

Managed PostgreSQL

primary state

PostgreSQL is the transactional authority and default consolidation point. Specialized stores appear only when a workload demonstrably exceeds its fit.

Azure Service Bus

async work

Queues, topics, dead-lettering, sessions, and the transactional outbox cover ordinary durable messaging. Event Hubs or managed Kafka is reserved for genuine streaming and replay topology.

OpenTelemetry → Azure Monitor

observability

Instrumentation remains portable while collection, storage, correlation, alerting, and operational presentation are managed.

Entra · Key Vault · App Configuration · conditional APIM

platform services

Identity, secrets, configuration, feature management, and API governance use managed services rather than adding self-hosted application platforms by default.

Bicep

infrastructure

An Azure-selected stack uses the shortest typed path to Azure resource APIs and what-if previews. Terraform remains the sanctioned path for inherited or genuinely multi-cloud estates.

Bounded monorepos

repository scope

Each coherent product or platform domain keeps its code, contracts, infrastructure, tests, instructions, and runbooks together without forcing every task to load the whole enterprise.

OpenAPI · OCI · OTel · PostgreSQL · OAuth/OIDC · Git

portable seams

Portability is concentrated in contracts, artifacts, telemetry, identity protocols, source, and the primary data model—not simulated across every managed implementation detail.

Managed coding-agent isolation

agent execution

Coding agents operate in managed sandboxes and produce pull requests. Product-side untrusted execution remains a separately governed capability with stronger isolation and egress controls.

Self-description and deterministic feedback

selection priority

Corpus matters, but types, schemas, analyzers, tests, plans, policy decisions, traces, and managed leverage dominate repeated operation and maintenance.

Operating position The stack is compiler-first at the application boundary and managed-first everywhere else. Agentic maturity is measured by reliable delegated change, not by how many control planes are exposed to an agent.
§2.0

Scope & Selection Rubric

Judgment under stated assumptions

Target: greenfield or substantially rebuilt business software, roughly 5–300 engineers, one primary cloud, moderate-to-high compliance, and agents performing most implementation and routine maintenance while humans retain product judgment and high-impact approval.

The rubric uses five axes. Recall remains useful, but a tool that is easy for a model to remember and expensive for a team to operate is still a poor default.

Code Axis / weight Question Low-score failure
CD Corpus density · 15% Does the model know the exact API, convention, and failure modes from abundant supported examples? Hallucinated methods, flags, and obsolete configuration.
IS Interface stability · 20% Will examples and generated code remain valid across the supported lifecycle? Version ambiguity and silent semantic drift.
SD Self-description · 25% Are contracts expressed by types, schemas, manifests, identities, ownership, and policy? Rules live in memory or prose and are broken invisibly.
FD Feedback determinism · 25% Can the agent converge through compiler, analyzer, test, plan, policy, and trace feedback? Vague, slow, flaky, or falsely green feedback.
ML Managed leverage · 15% How much patching, state, scaling, failover, security, and on-call work does the provider remove? The “agentic” stack becomes an operator-owned platform product.

Card scores are architectural judgment on a 0–5 scale, not benchmark measurements. The selected posture also depends on the stated Azure/.NET assumptions.

§3.0

Design Tenets

Referenced throughout
T-01Git is the change and evidence plane.

Code, schemas, infrastructure, policy, instructions, and privileged changes flow through reviewable diffs. Managed runtime values may live elsewhere, but never without ownership, schema, audit, and an API.

T-02Delete toil before making it legible.

A managed service that removes a control plane beats a self-hosted system merely because agents can edit its YAML.

T-03Compile before infer.

Prefer types, nullability, analyzers, source generation, schemas, and build-time contracts over conventions the model must remember correctly.

T-04Contracts exist at real boundaries.

OpenAPI, event schemas, tool manifests, and policy are mandatory where consumers or privileges diverge—not as decorative duplication inside one process.

T-05One paved shape, bounded context.

Stable repository and module layouts conserve agent context. Bounded monorepos preserve locality without turning the whole enterprise into one build graph.

T-06The feedback loop is the product.

Compiler, analyzers, real-dependency tests, browser traces, OpenAPI diffs, Bicep what-if, policy, telemetry, and evals must be fast and decisive.

T-07Modular monolith until evidence says otherwise.

Distributed boundaries consume the agent’s scarcest resource: coherent context. Extraction requires a measured seam and explicit migration contract.

T-08Managed runtime, immutable artifacts.

Build once, attest once, promote the same digest. Runtime reconciliation belongs to managed services, not hand-operated hosts or application-team clusters.

T-09No hidden write path.

Every UI action that affects code, data, identity, traffic, configuration, or models has a typed API, audit event, owner, and policy—even when a human uses the UI.

T-10Autonomy is capability-scoped and earned.

Agents receive short-lived identities and narrow tools. Higher autonomy follows eval history by task class; irreversible actions remain human-only.

§4.0

Reference System

Managed runtime + controlled agent loop

The critical separation is between change authority and runtime operation. GitHub is the task, code, review, CI, security, and evidence hub. Azure services reconcile and operate runtime state. The agent does not receive cloud credentials merely because it can author cloud changes.

§8.2 — Explicit anti-patterns

  • Kubernetes, Helm, Argo CD, service mesh, and cluster operators before a platform requirement exists.
  • MediatR, AutoMapper, FluentValidation, generic repositories, and “Clean Architecture” ceremony as mandatory defaults.
  • React, Next.js, GraphQL, Redis, Kafka, or a vector database introduced speculatively.
  • Agents with production shell, database admin, cloud admin, human credentials, or unrestricted internet egress.
  • One model vendor or model name embedded into architecture rather than an eval-governed implementation profile.
  • Console-only configuration, WAF rules, identity grants, production prompts, or feature flags with no exported policy.
  • Self-hosting identity, observability, gateways, catalogs, feature flags, or agent sandboxes without a quantified reason.
  • Multi-cloud wrappers that erase useful provider capabilities while failing to create a tested exit path.
  • CI secrets, publish profiles, shared service principals, mutable image tags, or environment-specific rebuilds.
  • Mocks declaring success for behavior owned by PostgreSQL, ASP.NET middleware, identity, or the browser.
  • Big-bang rewrites of inherited systems to achieve stack purity.
  • Metrics, dashboards, runbooks, documentation, or ownership that cannot be reached through a stable API or repository artifact.

Graduation, Waivers & Rollout

Complexity must pay rent
Stage Default contents Add only when Common forbidden shortcut
P0 · Repo-ready .NET 10, modular monolith, Razor Pages, PostgreSQL, devcontainer/Aspire, one check command. The first vertical feature can be built and tested end to end. Adding a second app language, service, or state store before the first feature.
