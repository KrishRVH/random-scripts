§1.0

Scope & Selection Rubric

Normative

This document is two things at once: a reference architecture with a strong point of view (§2–§3 and the normative groups A–H), and a decision standard broad enough to govern a full enterprise estate (groups I–S). It assumes a cloud-first deployment, roughly 50–500 engineers, and a compliance posture one notch below regulated-industry.

The organizing constraint is unusual: the primary operator of this stack cannot click, cannot remember yesterday, and cannot ask a colleague at the next desk. It reads text, writes text, and improves by iterating against machine feedback. Human ergonomics still matter — humans review, approve, and debug — but every tiebreak in this spec goes to the operator that does the volume work.

New build and existing estates. This standard defines the paved road for new build. Existing systems outside the paved road are governed through §8 with explicit exception posture, owner, controls, and review date.

Non-goals: vendor pricing, org design, model selection. Where a category is genuinely a coin flip (e.g. which SQL warehouse), the spec says so rather than manufacturing false precision.

§1.2 — Rubric: four axes, one scale

Every selection in §5 carries a score strip, and the §6 quadrant plots the same numbers — all scores in this document, including both chart axes, use the same 0–5 scale. Axes are ordered by weight: the first two measure how accurately a model already knows the tool; the second two measure how safely an agent can operate it without that knowledge being perfect.

Code Axis Definition Failure mode when low
CD Corpus density Volume of public code, docs, and Q&A the tool has accumulated. Determines recall of exact APIs, signatures, and idioms — recall scales with frequency of exposure, not per-example quality. Plausible-but-nonexistent methods; hallucinated flags and config keys.
IS Interface stability How consistently the public interface behaves. Stable APIs keep examples, docs, and generated code useful for the tool that is running. Ambiguous APIs, invalid configuration, and code that only looks correct.
SD Self-description Types, schemas, declarative manifests, machine-readable contracts. The degree to which the system states its own rules in-band. Contracts live in tribal knowledge; the agent breaks them silently.
FD Feedback determinism Quality and speed of the error loop: compilers, type checkers, dry runs, terraform plan. Agents converge by iterating against crisp failures. Vague or delayed failures; the agent iterates blind or, worse, believes it succeeded.
§2.0

Design Tenets

Referenced as T-nn throughout
T-01Git is the control plane.

Code, infra, schema, config, flags, docs, dashboards — every change is a text diff in one repository. A system that cannot be driven from a file in git is not adopted.

T-02Boring technology compounds twice.

Stable, widely deployed tools are simultaneously operationally proven and accurately recalled by models. Novelty is paid for out of the same error budget twice.

T-03Corpus beats elegance at the margin.

When two tools tie on technical merit, pick the one with a decade of public Q&A. Curated quality lifts a model's reasoning about a tool; only frequency lifts recall of its API surface.

T-04Schemas are the machine interface.

OpenAPI, SQL DDL, protobuf, strict TypeScript, typed Python. Every contract a checker can verify is a contract an agent cannot silently break.

T-05Convention over configuration, aggressively.

A predictable file layout is context the agent doesn't spend tokens rediscovering. One blessed shape beats infinite flexibility — this is why the spec prefers opinionated frameworks.

T-06The feedback loop is the product.

Compilers, linters, test suites, dry runs. Agents converge by iterating against crisp errors, so error-message quality and CI latency are first-class engineering concerns.

T-07Modular monolith before microservices.

Service boundaries fragment context, and context is the agent's scarcest resource. Split only at genuine scaling or ownership seams, never as a default posture.

T-08Declarative over imperative at runtime.

Desired-state systems (Kubernetes, GitOps, Terraform) are legible, diffable, and self-healing. Imperative runbooks are none of these.

T-09No invisible behavior.

Anything that alters traffic, data, or auth from outside the repo — mesh rules, GUI toggles, snowflake host configs — is illegible to the agent and eventually to everyone.

T-10Sandbox the agents; gate the blast radius.

Agents execute in microVMs with scoped, expiring credentials. Irreversible actions require a human signature. Autonomy is granted per tier and class (§7), earned by eval history.

Decision Library

122 selections · 19 groups · single data source

Each card records the pick, the sanctioned alternate (adopt without a waiver when the stated condition holds), and the avoid (requires a §8 waiver). Score strips use the §1.2 rubric: CD corpus density, IS interface stability, SD self-description, FD feedback determinism, each 0–5 for the pick as configured here. Cautions flag the known trap an agent will hit first.

122 decisions
GROUP A — LANGUAGES & CONTRACTS4 decisions · Ref. T-03, T-04
A1 · Backend languageCD IS SD FD
PickPython 3.14, uv-managed, mypy --strict
AltGo for hot-path daemons and CLIs
AvoidExotic or in-house languages
Largest code corpus, plus the corpus that matters more: intent-to-code mappings — millions of tutorials and Q&A threads translating requirements into implementation, which is most of an agent's actual job. Strict typing buys back the self-description Python lacks natively.
A2 · Frontend & tooling languageCD IS SD FD
PickTypeScript 5, strict
AvoidUntyped JavaScript in application code
Rides the full JavaScript corpus while tsc converts silent breakage into compile errors — the cheapest deterministic feedback loop in the estate (T-06).
A3 · Interface contractsCD IS SD FD
PickOpenAPI 3.2 + JSON Schema, spec-first
Altprotobuf/gRPC on measured internal hot paths
AvoidGraphQL as the default API layer (§8)
The contract is a file in the repo: clients are codegen'd, Schemathesis derives contract tests for free, and out-of-band change becomes a CI failure instead of a production incident.
CautionUse current OpenAPI tooling and keep generator, validator, and contract-test commands in CI.
A4 · Glue & automationCD IS SD FD
PickPython scripts + just task runner
AltMake — corpus king, arcane at scale
AvoidBash beyond ~50 lines
Bash quoting and portability footguns are precisely the error class agents commit with confidence. A justfile gives every repo one discoverable, self-documenting verb list.
CautionBash survives for one-liners; anything that remains passes shellcheck in CI.
GROUP B — APPLICATION LAYER5 decisions · Ref. T-05, T-07
B5 · Core backend frameworkCD IS SD FD
PickDjango 5.2 LTS — modular monolith
AltFastAPI for thin, typed service edges
AvoidBespoke micro-framework assemblies
Convention density is the argument (T-05): every Django codebase keeps models, views, urls, and migrations in the same place, so the agent navigates on priors instead of spending context discovering structure. FastAPI's type story is superb, but every FastAPI app is shaped differently — and for the core, convention beats type elegance.
CautionKeep business logic out of signals and middleware magic — invisible control flow violates T-09. Keep framework-specific conventions documented in the module instruction file.
B6 · Frontend frameworkCD IS SD FD
PickReact 19 + Vite SPA by default
AltNext.js 16 (App Router) where SSR/SEO is a hard requirement
AvoidAngular (§8)
Largest UI corpus in existence. React 19 + Vite keeps the default application shape a plain SPA — no server/client component boundary for the agent to misjudge.
CautionNext.js use requires App Router conventions, cache behavior, and framework commands documented in the module instruction file.
B7 · Styling systemCD IS SD FD
PickTailwind + shadcn/ui, components vendored in-repo
AltCSS Modules
AvoidRuntime CSS-in-JS
Utility classes make styling fully local — no cascade action-at-a-distance (T-09). shadcn components are editable source in the repo, not behavior hidden behind a package boundary.
B8 · Client data layerCD IS SD FD
PickTanStack Query
AltRTK Query in existing Redux estates
AvoidHand-rolled fetch/loading/retry state
Caching, retries, and invalidation as one heavily documented pattern. Hand-rolled loading-state machines are where subtle agent-authored bugs concentrate.
B9 · ORM & migrationsCD IS SD FD
PickDjango ORM + built-in migrations
AltSQLAlchemy 2 + Alembic on edges; Prisma on TS services
AvoidString-built SQL scattered through code
Schema changes become reviewable Python diffs with a dry-runnable plan — exactly the artifact the T2 gate (§7) demands attached to the PR.
CautionApplied migrations are immutable; enforce with a CI check, since editing history is a classic confident-agent move.
GROUP C — DATA PLANE9 decisions · Ref. T-02, T-03 · Postgres-maximalist
C10 · OLTP system of recordCD IS SD FD
PickPostgreSQL 18
AltAurora / Cloud SQL Postgres, managed
AvoidMongoDB as system of record (§8)
Deepest operational corpus of any database, and DDL is a self-describing contract the agent can read back at will. DDL, migrations, extensions, ownership, and backup posture are inspectable by agents before changes.
Caution18 defaults data checksums on at initdb — plan the flag before pg_upgrade from non-checksum clusters.
C11 · Postgres-maximalism boundaryCD IS SD FD
PickOne engine until it measurably hurts: JSONB documents, FTS, pgvector, SKIP LOCKED queues
AltGraduate per workload at proven thresholds (C13–C16)
AvoidA specialized store per feature
Every sidecar datastore is another API surface to recall, another consistency seam, another credential to scope. Fewer moving parts is an agent-legibility strategy before it is an ops strategy.
C12 · CacheCD IS SD FD
PickRedis API (Valkey)
AltMemcached for pure LRU byte caching
AvoidAd-hoc in-process caches
Enormous corpus, dead-simple semantics, one wire protocol every client library speaks.
C13 · Work queueCD IS SD FD
PickPostgres SKIP LOCKED → SQS at scale
AltRedis Streams for fan-out patterns
AvoidOperating a broker before you need one
A queue you can inspect with SQL is a queue an agent can debug. SQS adds effectively infinite scale behind a five-call API surface.
C14 · Streaming backboneCD IS SD FD
PickKafka 4.x (KRaft-only; 4.2+ for production Queues)
AltNATS JetStream — better ergonomics, thinner corpus
AvoidRabbitMQ for new event estates; new ZooKeeper deployments
T-03 in its purest form: NATS is arguably the nicer system, but Kafka's decade of publicly documented failure modes is a debugging asset the model already carries. NATS is the Rust of messaging — sanctioned via the docs-in-context quadrant (§6).
CautionUse KRaft-only operations and keep topic ownership, schemas, and replay procedures in the repo and registry.
C15 · SearchCD IS SD FD
PickPostgres FTS → OpenSearch at scale
AltElasticsearch where licensing permits
AvoidRunning a search cluster on day one
Start on the engine already running; graduate when relevance tuning or volume demands it. The query DSL is JSON — diffable, greppable, testable.
C16 · Vector storeCD IS SD FD
Pickpgvector → Qdrant at scale
AltManaged (e.g. Pinecone) when ops budget is zero
AvoidNovel vector databases
Embeddings live next to the rows they describe, inside transactions, under backups that already exist. The category change rates too fast to anchor on a dedicated store early (T-02).
C17 · Object storageCD IS SD FD
PickS3 — the API is the standard
AltMinIO self-host; GCS via interop
AvoidBlob columns; NFS shares
Possibly the most stable widely known API in the estate; presigned-URL and lifecycle patterns are corpus-saturated.
C18 · OLAP / warehouseCD IS SD FD
PickAny SQL warehouse — ClickHouse self-host, BigQuery/Snowflake managed
AltDuckDB for local and CI analytics
AvoidNoSQL query DSLs for analytics
A genuine coin flip on vendor, and the spec says so: the interface is SQL either way, and the corpus attaches to the language, not the engine (T-03).
GROUP D — TRAFFIC & COMPUTE7 decisions · Ref. T-08, T-09
D19 · Pipelines & transformationCD IS SD FD
Pickdbt + Airflow
AltDagster — typed and principled, thinner corpus
AvoidGUI ETL suites (§8)
dbt is SQL + Jinja + YAML tests living in a repo — near-perfect agent material. Airflow over Dagster is T-03 again; revisit as the Dagster corpus grows.
D20 · Edge & load balancingCD IS SD FD

AvoidHardware appliances; GUI-configured LBs

D21 · API gatewayCD IS SD FD
PickKong, declarative config in repo
AltCloud-native gateway
AvoidGUI-managed gateway policies
Rate limits and auth policies as YAML the agent can diff (T-01). The gateway UI is a read-only view, never the source of truth.
D22 · Service meshCD IS SD FD
PickNone by default
AltIstio ambient under a universal-mTLS mandate
AvoidSidecar-everything architectures
T-09 is the entire argument: traffic behavior defined outside the repository is invisible to the operator doing the work. NetworkPolicy plus ingress TLS covers the common need. Inherited meshes: see §8 postures.
D23 · ContainersCD IS SD FD
PickOCI images — multi-stage, distroless, digest-pinned
AltBuildpacks on golden paths
AvoidFat snowflake images; :latest tags
The Dockerfile corpus is enormous and the build loop fails crisply and locally — an agent iterates a broken build to green unaided (T-06).
D24 · OrchestrationCD IS SD FD
PickKubernetes, managed (EKS/GKE), Kustomize overlays
AltECS or Cloud Run below ~10 services
AvoidHand-rolled VM fleets; deep Helm template sprawl
Unmatched manifest corpus, fully declarative (T-08), and reconciliation is literally the change loop of Fig. 3-A running at the infrastructure layer.
D25 · Virtualization & sandboxingCD IS SD FD
PickKVM base · Firecracker microVMs for agent execution · devcontainers for dev parity
AltgVisor where microVMs don't fit
AvoidAgents executing on shared hosts with ambient credentials
The stack must contain its own operator. Millisecond-boot microVMs make a hard isolation boundary per task affordable — the same primitive serverless platforms trust to run hostile multi-tenant code (T-10).

E28 · Continuous deliveryCD IS SD FD

AltFlux
AvoidSSH-and-script push deploys
Desired state lives in git and the cluster converges toward it: deploy state becomes a diffable file, out-of-band change becomes an alert, rollback becomes git revert.

AvoidClickOps; console-originated changes

AvoidMock-everything unit suites

G39 · Dev environmentCD IS SD FD

§7.0

Autonomy Tiers, Classes & Promotion Evidence

Normative · reviewed quarterly

Autonomy is two-axis. Change tiers (below) govern what may be changed and with whose approval. Tool safety classes (R110, S0–S5) govern what may be read or touched while doing it. A T1 change executed with read-only tools and a T1 change wielding production-write tools are different risks; the policy gate evaluates both axes per action. Tiers are assigned per change class, not per agent; promotion is earned against the evidence table, never by ad-hoc exception.

Tier Posture Change classes Gate
T0 Autonomous — auto-merge Formatting and lint fixes · docstring/comment sync · documentation updates · dependency patch bumps within pinned ranges · new tests · telemetry annotations Green CI · size-capped diff · no CODEOWNERS paths touched
T1 Agent-authored — human-approved Feature code · refactors · non-breaking API additions · dashboard and alert definitions · feature-flag definitions · dependency minor bumps · agent prompt/config changes (R112) One reviewing engineer · full CI including contract tests
T2 Human-gated — two-party Schema migrations · IAM and authz policy · cost-bearing infrastructure · data backfills and deletions · production promotion · breaking API changes · security containment (J52) Two approvers incl. owner · dry-run artifact attached (plan, --check) · change window
T3 Prohibited to agents Direct production shell or DB access · secret values in context · spend approval · customer-data export · acknowledging pages (S120) · edits to this autonomy policy The policy file itself is CODEOWNERS-locked to humans (S117)

§7.2 — Promotion evidence

Thresholds below are the starting calibration for this estate profile, tuned quarterly against the eval dashboard (R113). The numbers may move; the requirement that promotion be numeric is normative.

Transition Required evidence
Enable T0 auto-merge ≥30 days in shadow mode (agent-authored, human-merged) · zero Sev-2+ incidents attributable to agent changes · revert rate <1% · scope limited to the listed T0 classes
T1 becomes default authorship ≥100 merged agent PRs · reviewer-override rate <10% · no recurring failure class across postmortems (N85) · eval suite at or above baseline on two consecutive runs
T2 drafting participation Dry-run artifact attached on 100% of attempts · rollback plan present · post-change verification green · owning-team sign-off on the arrangement
Demotion — automatic Any Sev-1 attributable to an agent change drops the affected change class one tier; re-promotion follows the same evidence path, no shortcuts
Standing rules — apply at every tier and class
  • Every agent action terminates in a git artifact: a commit, a PR, or a review comment. No side channels.
  • Credentials are scoped per task and expire with the sandbox (D25). Telemetry access is read-only.
  • Agents reference secrets by name (F33); resolution happens inside the runtime, never inside the context window.
  • Every agent is a first-class non-human identity (K64); the kill switch is credential revocation, not process hunting.
  • Autonomy assignments are re-derived quarterly from the eval dashboard (R113), in both directions.
§8.0

Waivers & Cuts

The exception process is part of the standard

A cut without an exception process is a rule people route around. Adopting anything from the table below — or departing from any §5 pick — requires a waiver record with owner, scope, compensating controls, review trigger, and return path. Postures: Tolerate (keep, with stated conditions) · Contain (keep, but freeze growth and fence with controls) · Migrate (funded path off, with a window).

Waiver record — waivers/*.yaml in-repo, referenced from the module's agent instruction file (R108)
  • id · decision ref · scope — which §5 selection or §8 cut is waived, and exactly where the waiver applies.
  • owner — a person, not a team alias; waivers whose owner departs auto-escalate.
  • expiry — maximum 12 months; renewal requires re-approval, not silence.
  • compensating controls — what fences the risk meanwhile: pins, lint fences, egress rules, extra review.
  • re-evaluation trigger — the event that reopens the decision early: major release, corpus shift, incident, staffing change.
  • migration path — the route back to the paved road, recorded even if currently unfunded.
